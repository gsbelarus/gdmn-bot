# Структура базы данных MongoDB для Zarobak Bot

## Обзор

Данный документ описывает структуру базы данных MongoDB для хранения данных чат-бота Zarobak. 
База данных заменяет файловую систему JSON и обеспечивает улучшенную производительность запросов и масштабируемость.

---

## Коллекции

### Коллекция Customer

Хранит информацию о предприятиях и организациях, использующих бота.

| Поле        | Тип      | Uq | FK | Описание                                        |
|-------------|----------|----|----|-------------------------------------------------|
| _id         | ObjectId |  * |    | Уникальный идентификатор                        |
| customerId  | String   |  * |    | Идентификатор предприятия (например, "bmkk")    |
| name        | String   |    |    | Полное наименование предприятия                 |
| protected   | Boolean  |    |    | Защита регистрации ПИН-кодом                    |
| aliases     | [String] |    |    | Альтернативные названия для поиска              |
| createdAt   | Date     |    |    | Дата создания записи                            |
| updatedAt   | Date     |    |    | Дата последнего обновления                      |

**Индексы:**
- `customerId`: уникальный
- `aliases`: текстовый индекс для поиска

## Диаграмма связей

```
Customer (1) ─────────────< (N) Employee
     │                              │
     │                              │
     └──────────< (N) AccDedRef     │
     │                              │
     └──────────< (N) Schedule      │
     │                              │
     └──────────< (N) CanteenMenu   │
     │                              │
     └──────────< (N) UserRight     │
                                    │
Employee (1) ──────< (N) AccountLink (для каждой платформы)
     │
     ├──────────< (N) Payslip
     │
     ├──────────< (N) PayslipItem
     │
     ├──────────< (N) Timesheet
     │
     └──────────< (N) Announcement (как отправитель/получатель)

Currency (1) ──────< (N) CurrencyRate
```

## Примечания по миграции

1. **Идентификаторы из файлов**: Текущая система использует составные идентификаторы вида `"147093200_735592262"`. Они сохраняются в полях `employeeId` для обратной совместимости с ERP-системой.

2. **Даты**: Все строковые даты (`"2020.1.31"`) преобразуются в объекты Date MongoDB.

3. **Локализованные названия**: Структура `LName` с `{ ru: { name: string }, en: ..., be: ... }` сохраняется.

4. **Данные платформ**: Коллекция `AccountLink` заменяет отдельные JSON-файлы для Telegram и Viber.

5. **Денормализация**: Рекомендуется встраивать часто запрашиваемые данные (текущее подразделение/должность) в `Payslip` для уменьшения количества соединений.
